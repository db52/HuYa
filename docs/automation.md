# 自动虎粮任务

本修复合并后，定时任务每天北京时间 **00:40**（UTC `40 16 * * *`）检查库存，固定送到房间 **998**。GitHub Actions 定时触发可能延迟或漏触发；改 cron 不代表已解决 GitHub 的调度延迟，也不能保证白天到账的临期礼物一定被覆盖。

仅赠送已在包裹中的普通 **虎粮** 和 **超粉虎粮**，不领取广告礼包、不购买礼物、不赠送其他付费礼物。两类库存来自同一次经过验证的接口响应；先送普通，再送超粉，各类需送礼业务回执与独立库存回读一致。任一提交失败、结果未知或库存后置条件不一致就停止，不自动重试。

手动执行默认为 `diagnose`，只查询登录与两类库存，不赠送；手动 `send` 才会送礼。原 `HUYA_ROOMS` Secret 保留但不再决定定时赠送对象；手动房间默认 998，可显式覆盖。

`result.json` 保留普通字段 `ordinary_huliang`、`submitted`，新增 `super_fans_huliang`、`super_fans_submitted`。旧结果缺少超粉字段时摘要显示未知，不伪造为零。

每次定时或手动 send 任务均向 Telegram「告警」话题 7388 发送一条两类库存、已确认赠送数量和运行链接；包括库存为空与失败。普通 diagnose 仍按失败／恢复去重，显式 test_notice 才发只读测试。通知不明不重试，同一 run 已尝试通知时不重复发送；历史查询失败保守停止通知。

PR 的安全测试不读取账号 Cookie，浏览器测试仅访问 localhost 礼物页面 fixture，不发生虎牙真实赠送。完整测试命令：

```bash
RUN_BROWSER_TESTS=1 python -m unittest discover -s tests -v
```

真实诊断须在指定分支手动选择 `diagnose`；通过测试不能替代真实超粉虎粮赠送验收。合并前默认分支仍采用旧时间和普通虎粮流程。
